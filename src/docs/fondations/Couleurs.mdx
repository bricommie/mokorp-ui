# Couleurs

Les composants consomment **uniquement** ces tokens sémantiques, via les utilitaires
Tailwind (`bg-primary`, `text-muted-foreground`, `border-input`, `ring-ring`…).
Les nuanciers et les contrastes ci-dessous sont **lus en direct** dans le thème : si
une valeur change dans `src/lib/theme/themes/*.css`, cette page suit.

Les ratios sont calculés selon WCAG 2.x. Seuils : **4,5:1** pour du texte, **3:1**
pour une bordure de contrôle, un indicateur ou un anneau de focus (WCAG 1.4.11).

> **Couples** : chaque fond a son texte associé, suffixé `-foreground`. On utilise
> toujours le couple ensemble : `bg-secondary text-secondary-foreground`, jamais
> `bg-secondary text-foreground`.

## Où vivent les valeurs

| Fichier                     | Contenu                                                                     |
| --------------------------- | --------------------------------------------------------------------------- |
| `theme/themes/light.css`    | Valeurs de la face claire (`:root`, `.light`)                               |
| `theme/themes/dark.css`     | Valeurs de la face sombre (`.dark`)                                         |
| `theme/tokens/states.css`   | États dérivés (`*-hover`) par `color-mix()`                                 |
| `theme/tokens/semantic.css` | Exposition à Tailwind (`@theme inline`) : `--color-primary: var(--primary)` |

Pour ajouter un token : le déclarer dans **les deux** faces, l'exposer dans
`semantic.css`, le documenter ici. Un token qui n'existe que dans une face est un bug.
